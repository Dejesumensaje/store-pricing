# UX/UI Audit — Store Pricing App
**Date:** 2026-06-30 | **Scope:** All flows and components | **Method:** Multi-agent static analysis of React/TypeScript source

---

## Executive Summary

- **Mandatory batch constraint is invisible at point of decision.** `ItemEditDrawer` (lines 320–327) tells directors their change is "ready to send" when it is actually unbatched and will not reach SAP until assigned to a batch — the most pervasive and highest-impact copy failure in the app (IE-06, IE-09, IA-04, IA-07).
- **Three destructive actions lack confirmation or undo.** `BatchDetailDrawer` Remove silently reverts an entire price override with no `ConfirmDialog` (BM-02); Move-to-batch fires immediately on `onChange` with no undo (BM-06); `ItemEditDrawer` `confirmRevert` state does not reset on item navigation, risking silent mutation of the wrong item (IE-01).
- **Accessibility violations span every major surface.** A skip-nav link is absent from `layout.tsx` (A11-09); `ScanOverlay`'s inline animation style defeats the OS reduced-motion preference (A11-08); `CollapsibleSection` `aria-controls` points to a non-existent DOM element when collapsed (IE-05); `ColumnsMenu` declares `aria-haspopup='menu'` over a `role='group'` popup (DT-06).
- **Dead code creates structural confusion.** `MainTabs.tsx` is never rendered (IA-01); `CHANGE_TYPE_TABS` routes exist nowhere in the app (IA-02); the entire split-pane `DataTable` branch is unreachable because `page.tsx` never passes the `splitPane` prop (DT-01); the `'draft'` batch status is never created but still branches throughout `BatchCard` and `page.tsx` (BM-01, BM-08).
- **Mobile and filtering interactions have critical gaps.** The `FilterDrawer` "Clear" button is approximately 16–18px tall, well below the 44px WCAG touch-target minimum (MOB-02); active filters become visually inaccessible when search opens on mobile (IA-09); `MobileItemList` communicates HQ review status only via a red left border with no ARIA equivalent (A11-01, A11-02).
